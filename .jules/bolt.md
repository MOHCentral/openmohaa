## 2024-05-24 - O(N^2) strlen in for loops
**Learning:** Found multiple instances where `strlen(s)` is called inside a `for` loop condition. Because `strlen` evaluates the length of the string on every iteration, and the compiler often cannot optimize it away (especially when passed via pointers where aliasing might happen, or lack of purity guarantees), this creates an O(N^2) bottleneck. For example, `Com_CharIsOneOfCharset` iterates over `set` checking for a matching character. By using `strchr` instead of manual iteration, we get an O(1) lookup that is heavily optimized in libc, or by simply caching `strlen` we turn O(N^2) into O(N).
**Action:** Replace manual character scanning loops that use `strlen` in the condition with standard C library functions like `strchr`, or cache the `strlen` result in a variable before the loop.
