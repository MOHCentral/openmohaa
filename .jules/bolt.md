## 2024-05-18 - Caching strlen in loop conditions for string manipulation
**Learning:** O(N^2) bottlenecks caused by recalculating `strlen(s)` inside for-loop conditions are prevalent across multiple modules (e.g., `code/client/cl_main.cpp`, `code/qcommon/q_shared.c`, `code/qcommon/common.c`, and tools). The string length can be cached locally (`size_t len = strlen(s);`) before the loop. Be careful when introducing new local variables inside a switch statement (as in `CL_CheckForResend`) by enclosing them in a scoped block `{}` to avoid 'jump to case label' compilation errors. Also, consider replacing `strlen` loops entirely with `strchr` when searching for single characters.
**Action:** When working on performance, always profile first, search the codebase for similar O(N^2) anti-patterns, and replace them with O(N) operations. Note scoping requirements when refactoring in C/C++.
