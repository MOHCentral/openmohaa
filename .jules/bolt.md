## 2024-05-24 - Avoid O(N^2) strlen in loops
**Learning:** Found multiple instances where `strlen()` is evaluated in loop conditions `for (i = 0; i < strlen(s); i++)`. Since compilers often cannot optimize this out due to potential aliasing or lack of purity guarantees, it creates an O(N^2) complexity bottleneck, especially when analyzing strings or commands in C/C++. We should prefer standard C functions like `strchr` when searching for a single character or caching the length into a local variable.
**Action:** When finding a loop that checks for a character match via `strlen`, replace it with an optimized approach like caching `strlen(s)` into a local variable or using `strchr`. Note that `strchr` returns a pointer to the character, which matches the behavior expected in `Field_FindFirstSeparator`.
