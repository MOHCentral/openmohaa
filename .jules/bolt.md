## 2024-05-24 - O(N^2) bottlenecks caused by `strlen()` in loop conditions
**Learning:** In C/C++, evaluating `strlen()` inside the condition of a `for` loop (e.g., `for (i = 0; i < strlen(s); i++)`) recalculates the string length on every iteration. For a string of length `N`, this causes the string to be traversed `N` times, turning an O(N) loop into an O(N^2) operation. When replacing these with O(1) character lookup functions like `strchr(set, c)`, we need to explicitly check if `c == '\0'` first, because `strchr` successfully matches the null terminator, whereas the original `strlen`-based loop condition excluded it, causing semantic differences.
**Action:** When finding `strlen()` in loop conditions, either cache the result outside the loop (e.g. `size_t len = strlen(s);`), use a direct null-terminator check (`s[i]`), or use a standard O(1) character lookup function like `strchr()` (with appropriate null-checks) to optimize to O(N) performance. Ensure comments are added to explain the optimization.
