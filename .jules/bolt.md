## 2024-05-19 - Replace strlen with strchr in character search loops
**Learning:** Found an O(N^2) bottleneck pattern specific to C parsing: using `strlen(set)` inside a loop condition `for( i = 0; i < strlen( set ); i++ )` for character matching. The compiler cannot automatically hoist `strlen` out of the loop because it's unsure if `set` might be modified or aliased. Replacing this pattern with `strchr(set, c)` changes it to O(1) matching. Crucially, `strchr` returns a pointer to the null terminator if `c == '\0'`, so if the original loop relied on stopping *before* the null terminator, you must explicitly check for `c == '\0'` first and return early to maintain the exact original behavior.
**Action:** When replacing `for` loops that use `strlen` with `strchr` for set matching, always check `if (c == '\0')` first and handle it exactly as the original loop did.
