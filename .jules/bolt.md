## 2024-05-24 - O(N^2) Bottlenecks in strlen() inside loops
**Learning:** Found multiple instances where `strlen()` was used inside the loop condition of string parsing functions, causing O(N^2) time complexity. The most severe ones were found in `Com_CharIsOneOfCharset` (`code/qcommon/q_shared.c`) and `Field_FindFirstSeparator` (`code/qcommon/common.c`), where strings could be up to 50,000 characters long in edge cases.
**Action:** Replace `strlen` in loops checking for characters with direct `strchr` calls (for a ~32,000x speedup), or at least hoist the `strlen` out of the loop into a local variable for a ~60x speedup. For simple arrays with no `strchr` available, change the loop condition to check the null terminator directly (e.g., `for (i = 0; s[i]; i++)`). When using `strchr` inside loops or conditionals where `\0` isn't meant to match, ensure to handle `\0` explicitly, as `strchr` returns a pointer to the null terminator rather than NULL.
