## 2024-03-24 - O(N^2) Performance Bottleneck in String Searches
**Learning:** In the Quake III / MOHAA codebase, there are multiple instances where `strlen()` is used directly inside `for` loop conditions for checking characters (e.g., `for( i = 0; i < strlen( set ); i++ )`). The compiler cannot reliably hoist the `strlen()` call out of the loop because strings might alias or the function might lack guaranteed purity, leading to an O(N^2) time complexity for what should be an O(N) operation.
**Action:** When searching for a character in a string, prefer using standard C library functions like `strchr()` which are optimized to run in O(N). If using a custom loop, always cache the result of `strlen()` in a local variable before the loop. When refactoring loop-based character searches to `strchr()`, always explicitly check for the null terminator (e.g. `if (c == '\0') return qfalse;`) as the original loops typically excluded it, whereas `strchr` successfully matches it.
