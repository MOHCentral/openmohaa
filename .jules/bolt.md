## 2024-05-13 - [O(N^2) Performance Pattern in C String Operations]
**Learning:** Found an anti-pattern in the codebase where `strlen()` is evaluated dynamically in `for` loop conditions. Since standard string lengths evaluate in O(N) time, looping over `strlen()` causes the entire operation to have O(N^2) time complexity. We observed this in strings that process up to maximum info string limit sizes. Replacing dynamic `strlen()` calls inside loop conditionals (or replacing with specialized C standard library functions like `strchr`) changes execution from O(N^2) to O(N) and results in massive speedups (up to 31,000x for 50,000 character buffers, and ~7x for 1,350 max info strings).
**Action:** When working in C/C++ string operations, look for and eliminate `strlen()` from loop conditions by caching its value in a size_t variable before the loop or leveraging specialized standard library functions (like `strchr`).
